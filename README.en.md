# media-content-distiller

English | [中文](README.md)

An independently installable audio/video subtitle and content distillation skill. It first obtains verifiable subtitles from Bilibili, YouTube, TikTok/Douyin, Xiaohongshu, podcasts, or other public media URLs, then uses Codex to produce transcripts, quick summaries, detailed summaries, structured outlines, learning notes, Q&A, or multi-video comparisons.

> Core boundary: BibiGPT is primarily used as a subtitle provider. The normal content path only calls `getSubtitle`; BibiGPT summary endpoints are not the default output engine.

## Capabilities

- Subtitle-first acquisition through the skill-owned Node.js API client: `/v1/me` then `/v1/getSubtitle`, with no dependency on another skill or command
- A bundled `media-content-distiller` CLI for public-URL acquisition, Token registry setup, normalization, rendering, and batch processing without Python or another skill
- Public media URL support; local media files fail safely before network access and are never uploaded automatically
- Normalization of `subtitlesArray`, `subtitles[]`, and Bilibili `body[]`, with timeline validation and timestamped transcript rendering
- Quick summaries, detailed summaries, structure/chapter summaries, learning notes, content Q&A, and batch comparisons generated by Codex from the same subtitle artifact
- Project-level Token registry with explicit-source precedence, hidden input, `0600` permissions, balance preflight, and stop-on-error behavior without automatic rotation
- Redacted raw responses, metadata, status, and transcript artifacts, with main products separated from source sidecars
- Ego Lite only as an explicitly requested visible-browser validation path or a fallback when the API is unavailable; it does not silently switch to another browser

## Installation

After pushing this repository to GitHub, install it with the Skills CLI:

```bash
npx skills add <owner>/<repo> --skill media-content-distiller -g -y
```

If the repository root contains this skill, `--skill` can be omitted:

```bash
npx skills add <owner>/<repo> -g -y
```

Install it for selected agents:

```bash
npx skills add <owner>/<repo> --skill media-content-distiller -a codex -a claude-code -y
```

Verify discovery and installation locally:

```bash
npx skills add . --list
npx skills add . --skill media-content-distiller --copy -y
```

When publishing to GitHub, replace `<owner>/<repo>` with the actual repository. This repository does not create remotes or push code automatically.

### Install the bundled CLI

The CLI requires Node.js 18+ and has no third-party npm or Python dependency:

```bash
npm install --global .
media-content-distiller --help
```

Or run it directly from a checkout:

```bash
./bin/media-content-distiller --help
```

From GitHub:

```bash
npm install --global github:Dithob/media-content-distiller
```

## Quick start

### 1. Use the bundled CLI

```bash
media-content-distiller subtitle \
  --url "https://example.com/video" \
  --output-dir ./media-artifacts
```

The skill-owned Node.js CLI calls the BibiGPT API directly: it performs `/v1/me` preflight,
then calls `/v1/getSubtitle`. It uses only this skill's API client and never calls another
skill or BibiGPT summary endpoints.

### 2. Local media files

The current BibiGPT API accepts public media URLs only. A local file is rejected before
network access; it is not uploaded or sent to the API:

```bash
media-content-distiller subtitle \
  --input "/path/to/local-media.mp4" \
  --output-dir ./media-artifacts
```

The command reports that a public media URL is required. For an existing local subtitle
JSON artifact, use the offline `normalize` and `render` commands instead.

### 3. Python compatibility/API entry point

```bash
python3 scripts/acquire_subtitle.py subtitle \
  --input "https://example.com/video" \
  --output-dir ./media-artifacts
```

The Python entry point remains for existing callers and script environments. Its API
mode accepts URLs only; it does not upload local files directly. Before requesting
subtitles, it calls `/v1/me`, then `/v1/getSubtitle`. On 401, 402/403, 429, exhausted
quota, empty subtitles, or invalid timelines, it stops and reports the failure instead
of marking the task complete. New users without Python should use the bundled Node.js
CLI.

### 4. Render an existing local subtitle JSON artifact offline

```bash
media-content-distiller normalize --input ./raw-subtitle.json
media-content-distiller render \
  --subtitle ./raw-subtitle.json \
  --metadata ./metadata.json \
  --out-dir ./media-artifacts/source-id

# Python compatibility commands remain available:
python3 scripts/normalize_subtitle.py --input ./raw-subtitle.json
python3 scripts/render_transcript.py \
  --subtitle ./raw-subtitle.json \
  --metadata ./metadata.json \
  --out-dir ./media-artifacts/source-id \
  --artifact-id source-id
```

By default, every 10 cues are grouped into one time range and cues are separated by line breaks. Use `--sentences-per-group 1` for cue-by-cue output. Use `--sentence-separator '|'`, `space`, or a custom string for another separator.

## Credential configuration

Never paste Tokens into chat, ordinary command arguments, Git, skill files, or generated artifacts. Available options include:

```bash
# Use one Token in the current process
export BIBI_API_TOKEN="<user-authorized-token>"
```

```dotenv
# Project .env: one Token
BIBI_API_TOKEN=<user-authorized-token>

# Or a multi-Token registry pointer (choose one; do not configure both)
# BIBIGPT_TOKEN_REGISTRY=./accounts.json
```

During an interactive task, the bundled CLI can initialize a registry through hidden
input. In a non-TTY environment, configure credentials first or run:

```bash
media-content-distiller setup \
  --registry ./accounts.json \
  --env-file ./.env \
  --acknowledge-plaintext-token-storage
```

Import authorized Tokens in batch:

```bash
media-content-distiller import \
  --registry ./accounts.json \
  --input ./tokens.txt \
  --acknowledge-plaintext-token-storage
```

Bind an existing registry:

```bash
media-content-distiller bind \
  --registry ./accounts.json \
  --env-file ./.env
```

Python registry commands remain available for compatibility:

```bash
python3 scripts/token_registry.py repair ...
python3 scripts/token_registry.py import ...
```

The registry and `.env` are best-effort protected with `0600` permissions and are ignored by this repository's `.gitignore`. The tools do not register accounts, collect cookies, process CAPTCHA challenges, switch accounts automatically, rotate Tokens, or bypass quotas.

## Artifact layout

```text
media-artifacts/
├── README.md
├── <title>.md                # Main Codex-generated product
└── <source-id>/
    ├── README.md
    ├── raw-subtitle.json     # Redacted subtitle response
    ├── metadata.json
    ├── transcript.md
    └── status.json
```

Main products belong in the root of `media-artifacts/`; subtitle-acquisition sidecars belong in the source-ID directory. Main products should contain a `## Sidecar navigation` section, while the root index and source-directory README should link back to each other. Do not describe a grouped transcript as an official word-for-word transcript: it is a readable rendering based on the selected grouping settings, while complete cues remain in the redacted raw JSON.

## Validation

No network access or real API Token is required:

```bash
node scripts/verify_cli.mjs
npm run test:cli
python3 scripts/verify_skill.py
python3 -m unittest discover -s tests -v
```

On macOS, if the default Python cache directory is restricted:

```bash
PYTHONPYCACHEPREFIX=/tmp/media-content-distiller-pycache \
  python3 scripts/verify_skill.py
```

The Node checks cover syntax, CLI help/version, `/v1/me` → `/v1/getSubtitle` request order,
summary-endpoint exclusion, safe local-file failure before network access, batch processing,
subtitle shape/timeline validation, grouped rendering, redaction, and registry permissions.
The Python checks cover compatibility entry points and repository structure.

These offline checks and fixtures validate local code paths and safety boundaries only. They do not prove that a real BibiGPT account, paid quota, network connection, or current server response is available.

## Release checklist

1. Confirm that the repository contains only skill code, documentation, tests, and example configuration—not `.env`, `accounts.json`, real Tokens, cookies, caches, or media artifacts.
2. Run `node scripts/verify_cli.mjs`, `npm run test:cli`, `python3 scripts/verify_skill.py`, and `python3 -m unittest discover -s tests -v`.
3. Initialize Git, commit the changes, and push to a public GitHub repository.
4. In a clean directory, run `npx skills add <owner>/<repo> --list` and confirm that `media-content-distiller` is discoverable.
5. Run `npx skills add <owner>/<repo> --skill media-content-distiller --copy -y`, then run the offline verification again.
6. Only perform a live API verification with a legitimate authorized account and acceptable quota; record network, quota, and server-side failures separately.
